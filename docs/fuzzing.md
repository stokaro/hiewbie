# Bounded fuzzing and portable replay

Issue [#28](https://github.com/stokaro/hiewbie/issues/28) adds five bounded
invariant handlers, deterministic corpus replay, and a separate libFuzzer
campaign. The production core does not depend on libFuzzer, a nightly compiler,
Python, Node, or a C++ runtime.

The [replay crate](../fuzz/replay/src/lib.rs) supplies the same handlers to three
input producers: workspace tests and the stable `replay` command, a small
WebAssembly replay adapter, and coverage-guided libFuzzer targets. A passing
fixed corpus is deterministic regression evidence. A passing guided campaign
also requires observed executions and nonzero coverage; neither establishes
complete format or command compatibility.

## Tested boundaries

| Target | Properties and independent checks |
| --- | --- |
| `formats_symbols` | PE, ELF, Mach-O, fat Mach-O and TE parsing; bounded entries, fields, records, notes, slices, names, retained text and source reads; record/target spans remain inside their selected image; valid symbol/relocation/debug/thread-state seeds; short reads and a sparse virtual source so large count/offset fields reach checked arithmetic; raw bytes, generation and pending edits remain unchanged after success, unknown magic or failure |
| `decoder` | All six implemented modes: x86-16/32/64, ARM, Thumb and AArch64; both byte-order requests; invalid/truncated encodings, bounded instruction text, nonzero progress, raw-byte identity, addresses near overflow and raw fallback after unsupported interpretation |
| `addresses` | File offsets, virtual addresses, image bases and slices; a separate `u128` interval model checks mapped, unmapped, zero-fill, ambiguous and overflowing translations; absolute/relative goto parsing remains within the document |
| `search` | Byte and UTF-8 requests, ASCII case folding, forward/backward search, scopes and even-offset filtering; a separate brute-force matcher checks results; zero/nonzero step budgets, short reads, progress, completion, stale generations and rejected oversized patterns |
| `edit_commands` | A bounded full-byte snapshot model checks the core's sparse overlay, cursor, edit/read-only state, mode, generation and undo/redo effects across command sequences; out-of-range/oversized edits and rejected commands preserve bytes and history; save completion, discard, undo and redo have explicit expected transitions |

Each input is at most **4,096 bytes**. The edit model uses at most 64 document
bytes and 128 commands; the address model uses at most eight regions. Parser and
symbol readers retain their separate production limits, including 1 MiB and
8 MiB source-read budgets respectively. The counting source checks actual read
work even for short reads. Symbol-name limits apply to source bytes: lossy
UTF-8 output can be three times larger, while the retained-text budget still
applies to its actual output size.

These handlers supplement the existing unit and integration tests. They do not
exercise terminal input, filesystem save failures, every history-capacity limit,
all legacy executable formats, production text assembly, or a browser frontend.
The portable extension API and loader remain unavailable under
[#82](https://github.com/stokaro/hiewbie/issues/82); there is no invented extension
input target. Add one when a real input boundary exists, retaining allocation,
capability and no-mutation properties at that boundary.

## Corpus provenance and stable replay

All initial seeds are generated by original MIT-licensed hiewbie code in
[`corpus.rs`](../fuzz/replay/src/corpus.rs) and the existing
[`symbol_images.rs`](../tests/fixtures/symbol_images.rs),
[`te_images.rs`](../tests/fixtures/te_images.rs), and
[`macho_images.rs`](../tests/fixtures/macho_images.rs) fixture generators.
The ELF and Mach-O layouts are constructed from published format fields;
[references and reuse](references-and-reuse.md#symbol-table-format-references-and-fixture-provenance)
records the primary specifications. No proprietary HIEW binary, manual excerpt,
or downloaded executable sample is included.

Seeds include empty/all-zero/all-one data, valid PE/ELF/Mach-O symbol tables,
fat slices, large PE offsets/counts, lossy export names, each decoder mode,
overlapping/zero-fill mappings, search variants, and editable/read-only/empty
transactions. Tests require the valid format seeds to reach actual symbol
records. TE seeds compact alignment padding while preserving a complete legal
header, entry, relocation and debug payload within the 4,096-byte input budget;
a known-answer test requires the real parsed records and entry offset. Mach-O
seeds add baseline thread states in both byte orders, high-VM backing, object
relocations and modern entry metadata. Fixed replay also tries deterministic
truncations and bit flips. Those
mutations are deliberately described as corpus replay rather than guided
fuzzing.

Run from the repository root with the pinned stable toolchain:

```sh
cargo +1.90.0 test --locked --package hiewbie-fuzz-replay
cargo +1.90.0 run --locked --package hiewbie-fuzz-replay --bin replay
cargo +1.90.0 run --locked --package hiewbie-fuzz-replay --bin replay -- --list
cargo +1.90.0 run --locked --package hiewbie-fuzz-replay --bin replay -- --write-corpus target/fuzz-corpus
```

`cargo xtask check` includes the replay crate's tests. The stable command accepts
a single saved input without libFuzzer or sanitizers:

```sh
cargo +1.90.0 run --locked --package hiewbie-fuzz-replay --bin replay -- \
  --replay formats_symbols path/to/crash-artifact
```

Unknown targets, nonregular files and artifacts larger than 4,096 bytes are
errors. Oversized input is rejected instead of silently testing a truncation.
Keep a minimized regression in the source-generated corpus, with its defect
reference and provenance, once the parser/model defect is fixed.

## Prepare once, then run offline

The guided runner requires Python 3.11 or later, a POSIX host and its native
C/C++ build toolchain. The CI campaign uses Ubuntu 24.04. Fetch tools and the
locked dependency graphs while network access is available:

```sh
rustup toolchain install 1.90.0 --profile minimal
rustup toolchain install nightly-2025-09-18 --profile minimal
cargo +1.90.0 install cargo-fuzz --version 0.12.0 --locked
cargo +1.90.0 fetch --locked
cargo +nightly-2025-09-18 fetch --locked --manifest-path fuzz/libfuzzer/Cargo.toml
```

Then run the bounded campaign:

```sh
python3 -m unittest discover -s fuzz -p 'test_run.py' -v
python3 fuzz/run.py
python3 fuzz/run.py --target search --target edit_commands --seconds 10 --output target/fuzz-focused
python3 fuzz/run.py --campaign --output target/fuzz-scheduled
```

`run.py` sets `CARGO_NET_OFFLINE=true`, checks the pinned `cargo-fuzz` version,
validates the manifest/nightly pins, uses locked stable corpus preparation and
locked fuzz metadata, and rejects fuzz-lockfile changes. A Cargo environment
wrapper can be supplied with `--cargo PATH`; it must forward `+TOOLCHAIN` and
subcommands normally. Output directories are local/ignored evidence, and a
directory already containing `manifest.json` is rejected to preserve its run.

| Limit | Pull request / normal invocation | Scheduled / `--campaign` |
| --- | --- | --- |
| Guided time per target | 20 seconds | 300 seconds |
| Targets | All five unless explicitly selected | All five unless explicitly selected |
| Single-input timeout | 5 seconds | 5 seconds |
| RSS / single-allocation limits | 512 MiB / 64 MiB | 512 MiB / 64 MiB |
| Maximum input | 4,096 bytes | 4,096 bytes |
| Initial random seed | 20261128 | 20261128 |
| Sanitizer / assertions | AddressSanitizer, debug assertions and overflow checks | Same |

The harness adds a process-group deadline of the selected time plus 60 seconds
per target. Corpus preparation, locked metadata and the instrumented build have
300-, 60- and 900-second deadlines respectively. Deadline cleanup terminates the
whole process group, including a surviving descendant after Cargo exits. A
nonzero exit, deadline, missing executions or missing coverage fails the run.
The small Python tests exercise those reporting/cleanup paths with fake tools;
they do not stand in for the actual sanitizer campaign.

`ASAN_OPTIONS` and `LSAN_OPTIONS` are inherited unchanged and recorded. In an
environment where LeakSanitizer reports that it cannot run under `ptrace`, keep
that failed run and use a fresh output directory for an explicitly qualified
rerun with `ASAN_OPTIONS=detect_leaks=0`. Such a rerun retains AddressSanitizer
but does not test leaks. The runner never disables leak detection automatically,
and CI leaves the sanitizer defaults enabled.

## Reproduce and minimize a guided failure

Retain the manifest, target log and original crash/timeout artifact together.
Replay a core assertion with the stable command first. Reproduce sanitizer-only
failures with the same pinned nightly, environment and instrumentation; a
successful unsanitized replay does not dismiss a sanitizer failure:

```sh
CARGO_NET_OFFLINE=true cargo +nightly-2025-09-18 fuzz run \
  --fuzz-dir fuzz/libfuzzer --sanitizer address --debug-assertions \
  formats_symbols path/to/crash-artifact -- \
  -runs=1 -timeout=5 -rss_limit_mb=512 -malloc_limit_mb=64 -max_len=4096
```

On the Linux campaign host, bound minimization as well. The example uses GNU
`timeout` to cap the entire command, including build/startup, and libFuzzer's
own input/time limits:

```sh
CARGO_NET_OFFLINE=true timeout --signal=TERM --kill-after=5s 180s \
  cargo +nightly-2025-09-18 fuzz tmin \
  --fuzz-dir fuzz/libfuzzer --sanitizer address --debug-assertions --runs 255 \
  formats_symbols path/to/crash-artifact -- \
  -max_total_time=60 -timeout=5 -rss_limit_mb=512 -malloc_limit_mb=64 -max_len=4096
```

Keep the original artifact if minimization fails or expires. Replay the resulting
artifact against the same target before adding it as a regression; compare the
failure with the independent oracle before changing production semantics.

## Portable WASM replay

The small adapter exports an integer-only entry point and does not import host
functions. It executes the same source-generated seeds and deterministic
mutations in Node's WebAssembly engine. This is executed WASM evidence, not
browser UI, browser storage or full release-matrix qualification.

```sh
rustup target add --toolchain 1.90.0 wasm32-unknown-unknown
cargo +1.90.0 fetch --locked --manifest-path fuzz/wasm/Cargo.toml
CARGO_TARGET_DIR=target/fuzz-wasm cargo +1.90.0 build --locked --offline --release \
  --manifest-path fuzz/wasm/Cargo.toml --target wasm32-unknown-unknown
cargo +1.90.0 run --locked --offline --package hiewbie-fuzz-replay --bin replay -- \
  --write-corpus target/fuzz-wasm/corpus
node fuzz/check-wasm.mjs \
  target/fuzz-wasm/wasm32-unknown-unknown/release/hiewbie_fuzz_wasm.wasm \
  target/fuzz-wasm/corpus > target/fuzz-wasm/replay.json
```

The checker requires all five target replays to return positive case counts and
an invalid target index to return zero. A compile, import, execution or corpus
failure produces a failed JSON report and a nonzero exit. Generate the corpus
from the same source checkout used for the module. Its hash describes those
source-generated seed bytes; the module hash identifies the linked binary.
WASM executes the corpus compiled into that module, not files loaded by the JS
checker. Do not pair an older module with a changed generator and claim matching
source evidence.

## Evidence and CI

The [fuzz workflow](../.github/workflows/fuzz.yml) configures the 20-second
campaign on pull requests and main pushes, the 300-second campaign on the daily
schedule, and portable WASM replay. Manual dispatch uses the shorter budget.
The guided job has a 45-minute outer limit and the WASM job a 10-minute limit.
Run metadata, logs, corpus files and crash artifacts are retained for 14 days;
portable evidence also retains its linked module. These are configured jobs;
only their actual retained results establish a particular run's success.

Native campaign manifests record the commit, `working_tree_dirty`, source hash,
tool versions and lock hash, exact commands, sanitizer environment, budgets,
initial/final corpus digests, elapsed time, exits, execution counts and observed
coverage edges. WASM reports record the commit and dirty state, the same source
hash algorithm, initial corpus digests, linked-module SHA-256, Node version and
per-target case counts. Failed runs remain failed, including tooling or
instrumentation failures.

Source hashing covers tracked and nonignored new files under `fuzz/`,
`crates/hiewbie-core/`, `tests/fixtures/`, plus the root Cargo manifest and lock.
For each sorted relative path, hash its UTF-8 path, a NUL delimiter, and the
binary SHA-256 of its contents into the final SHA-256. Corpus digests use the
same framing for regular files relative to the corpus directory and include
the file count. Empty seed files are included. Generated outputs belong in the
ignored result/target directories so they cannot become source or fixtures by
accident.

Native fixed replay is part of ordinary workspace tests on the configured
native host matrix. Guided Linux execution and Node WASM execution do not
establish native RISC-V, FreeBSD, browser, or missing format/extension support.
The [capability contract](capabilities.md), [compatibility ledger](compatibility-status.md)
and [build matrix](build-and-release.md#3-required-build-matrix) retain those
separate implementation and runtime requirements.
